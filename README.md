# 제타 AI 기억력 보조 (Zeta Memory Assistant)

> 제타(Zeta) 롤플레잉 채팅에서 과거 대화를 보관하고, Gemini API로 서사·인물·관계·설정을 정리하며, 과거 이야기 상기와 모순 정정을 돕는 **비공식 Tampermonkey 유저스크립트**입니다.

**현재 버전: `0.0.4` (베타)**  
**대상 사이트:** `https://zeta-ai.io/*`, `https://*.zeta-ai.io/*`  
**지원 목표:** 데스크톱 브라우저 및 iPhone/iPad Safari + Tampermonkey

> [!WARNING]
> 현재 베타 버전입니다. 브라우저별 작동, 제타 사이트 개편에 따른 호환성, 특히 모바일 Safari의 페이지 통신과 오래된 메시지 위치 이동은 완전히 검증되지 않았습니다. 중요한 기록은 정기적으로 JSON 백업하세요.

## 빠른 설치

1. 브라우저에 **Tampermonkey**를 설치하고 활성화합니다.
2. **[유저스크립트 설치/열기](https://raw.githubusercontent.com/casualJH/zeta-memory-assistant/main/zeta-memory-assistant.user.js)** 에서 `zeta-memory-assistant.user.js`를 설치합니다.
3. `https://zeta-ai.io/`의 **실제 채팅방**을 열고 새로고침합니다.
4. 화면에 나타나는 **「기억 보조」** 버튼을 눌러 패널을 엽니다.
5. **설정**에서 자신의 Gemini API 키를 입력하고 저장합니다.
6. **현황 → 과거 대화 전체 불러오기**를 눌러 수집이 완료될 때까지 확인합니다.
7. **미분석 대화 요약**을 실행하거나 자동 분석이 켜져 있으면 자동 분석이 시작되는지 확인합니다.

Gemini API 키는 Google AI Studio에서 직접 발급해야 합니다. 모델 이용량·요금·사용 제한은 Google의 정책과 실제 계정 상태에 따릅니다.

- Google AI Studio: https://aistudio.google.com/apikey
- Gemini API 안내: https://ai.google.dev/gemini-api/docs

## 1. 전체 대화 수집 및 로컬 저장

- 제타가 사용하는 메시지 API를 참고해 **채팅방별** 대화를 가져옵니다.
- 처음 실행 시 **「과거 대화 전체 불러오기」**를 누릅니다. 응답의 페이지 커서(`nextCursor`)를 따라 이전 메시지를 순차 수집합니다.
- **「최신 대화 확인」** 버튼으로 이후 메시지를 확인할 수 있습니다.
- 일반 대화(`TEXT`)와 구조화된 상태창(`INFO_BOX`) 내용을 처리합니다.
- 원본 메시지 ID, 내용 부분별 ID, 발화자, 내용, 원본 전송 시각 등을 기록해 나중에 **근거 확인**에 활용합니다.
- 같은 채팅방의 원문과 기억은 브라우저의 **IndexedDB**에 저장됩니다. 브라우저를 닫고 다시 열어도 일반적으로 유지되지만, 사이트 데이터 삭제·브라우저 저장 공간 정리·비공개 모드 등에 따라 지워질 수 있습니다.
- 전체 수집이 마지막 페이지까지 완료되었다고 확인되어야 **초기 요약 분석**을 진행하도록 설계되어 있습니다. 부분 수집 시 누락 가능성을 알립니다.

**중요:** 실제 대화 수집 가능 여부는 로그인 인증 감지 및 제타 API 구조에 영향을 받습니다. 사이트의 API 또는 브라우저 실행 환경이 바뀌면 수집이 실패할 수 있습니다.

## 2. Gemini 서사 요약과 누적 기억

기본 모델 설정은 `gemini-2.5-flash`입니다. Gemini API 키를 등록해야 AI 분석·자연어 답변이 작동합니다.

1. 원문을 수집하면 아직 분석하지 않은 **메시지 그룹**만 선택합니다.
2. 긴 대화는 길이 제한에 맞춰 여러 묶음으로 나누어 Gemini에 전달합니다.
3. Gemini가 사건, 핵심 사실, 등장인물, 관계, 복선, 인물별 지식, 모순 의심 사항을 구조화된 JSON 형태로 제안합니다.
4. 스크립트는 응답에 포함된 **원문 ID가 실제 수집된 메시지인지** 확인한 후 누적 기록에 반영합니다.
5. 처리된 메시지 ID를 저장하여 다음 실행에서는 **미분석 대화** 위주로 처리합니다.

### 반드시 지키도록 요청하는 요약 원칙

- 실제 사용자 대화와 캐릭터가 출력한 지문만 근거로 기록합니다.
- 실제로 없던 사건·설정·대사를 새로 만들지 않도록 지시합니다.
- **직접 인용은 원문에 존재하는 대사만** 큰따옴표로 표시하도록 요청하고 검사합니다.
- OOC 지시나 요약 요청 자체를 서사 속 실제 사건으로 취급하지 않도록 지시합니다.
- 추측·거짓말·복선·반전을 곧바로 확정 사실이나 오류로 단정하지 않도록 지시합니다.

> AI 분석은 완벽하지 않습니다. 원문 확인과 수동 편집을 함께 사용하세요. 새 대화마다 Gemini 호출이 발생할 수 있으므로 API 사용량이 늘어날 수 있습니다.

## 3. 날짜 표기: 작품 속 실제 날짜 → D+N

채팅 메시지의 **실제 전송 시각은 서사 날짜로 사용하지 않습니다.**

1. 작품 내에서 **연도·월·일이 명시된 날짜**를 확인할 수 있다면 `2026년 3월 15일`처럼 표시합니다.
2. 정확한 날짜가 없는 이야기 구간은 `D+1`, `D+2` … 형태의 상대 날짜로 기록합니다.
3. `다음 날`, `사흘 뒤`, `일주일 후` 등 **명확하게 계산할 수 있는 시간 경과 표현**을 사용합니다.
4. 시간 경과가 불분명하면 근거 없이 다음 날로 넘기지 않도록 설계합니다.
5. 날짜를 확정할 수 없는 경우 별도로 처리할 수 있습니다.

**주의:** 자동 날짜 추론은 실제 이야기의 시간 흐름을 완벽하게 이해하는 기능이 아닙니다. 긴 회상, 시간 역행, 여러 세계관 날짜가 섞인 장면은 직접 확인해야 합니다.

## 4. 인물 카드와 관계 기억

**인물·관계** 탭에서 아래 기록을 확인합니다.

- 인물별 이름, 성격·특징, 가족 관계, 비밀
- 두 인물 사이의 현재 관계
- 관계가 변화한 이력

기억 카드의 **편집** 버튼으로 내용을 수정할 수 있습니다. 사용자가 직접 수정한 항목은 자동 AI 분석이 임의로 덮어쓰지 않도록 보호합니다. 불필요한 기억은 삭제할 수 있습니다.

## 5. 핵심 설정, 복선, 인물별 지식

**설정·복선** 탭에서 다음 항목을 관리합니다.

- **사용자 고정 지침:** 서사에 반드시 적용하고 싶은 설정을 직접 입력·저장
- **핵심 설정:** 중요한 사실을 개별 항목으로 관리하고 중요도 설정
- **복선·미해결 사건:** 미해결(`open`), 해결(`solved`), 보류(`hold`) 상태 기록
- **인물별 지식:** 특정 인물이 내용을 알고 있음(`knows`), 모름(`unknown`), 일부만 앎(`partial`) 등을 구분

기억 항목의 중요도는 **핵심(`critical`) / 중요(`high`) / 일반(`normal`) / 낮음(`low`)**으로 나눕니다. 사용자가 직접 고정한 사실은 상기문에도 우선 포함됩니다.

## 6. 모순 감지 및 정정문 복사

새 캐릭터 지문을 과거 기록과 비교해 **서사 불일치 의심**을 제안합니다.

예를 들어 과거에는 외동이라고 밝혔는데 최근 지문에서 형이 등장하는 상황처럼, 기존 기록과 충돌할 가능성이 있는 경우:

- 문제로 판단한 **최신 지문 원문**
- 모순이 의심되는 **이유**
- **과거 원문 근거**로 연결되는 버튼
- 이야기 흐름을 유지하기 위한 **정정 제안**

을 표시합니다.

**「모순 정정문 복사」** 버튼을 누르면 열려 있는 모순 의심들을 묶어 클립보드에 복사합니다. 개별 항목의 **「이 오류 복사」**, 잘못 감지된 항목의 **「오류 아님」** 처리도 가능합니다.

> 의도적인 반전·거짓말·인물의 오해를 실제 오류로 잘못 분류할 수 있습니다. **모순 의심**은 AI의 제안일 뿐, 확정 판정이 아닙니다. 화면의 문장 강조 및 위치 찾기 역시 제타의 렌더링 상태에 따라 동작이 달라질 수 있습니다.

## 7. 자연어 기억 검색

**기억 검색** 탭에서 다음과 같이 질문할 수 있습니다.

- “첫 고백이 언제였지?”
- “둘이 처음 화해한 날은?”
- “민준이 아직 모르는 비밀이 뭐야?”

두 종류의 검색을 지원합니다.

- **기록 검색:** 로컬에 저장된 사건·설정·원문에서 관련 내용을 찾습니다. Gemini API 호출이 필요하지 않습니다.
- **AI 자연어 답변:** 로컬 검색으로 수집한 근거와 누적 기억을 Gemini에 전달해 질문에 답하도록 합니다. **API 키와 호출 비용**이 필요합니다.

검색 결과에 원문 근거 ID가 있으면 누르면 해당 원문을 볼 수 있습니다. 근거가 부족한 경우 답을 추측하지 않도록 지시하지만, AI 결과를 원문과 대조하는 것이 안전합니다.

## 8. 실제 대화 원문 확인 및 위치 이동

사건 또는 기억에 연결된 **「원문」** 버튼을 누르면 저장된 메시지를 열람할 수 있습니다.

원문 보기에서 **「실제 말풍선으로 이동」**을 누르면:

1. 현재 화면에서 해당 메시지 ID 또는 원문 내용이 맞는 말풍선을 검색합니다.
2. 발견하면 해당 말풍선 위치로 이동하고 강조합니다.
3. 화면에 아직 없는 과거 메시지는 스크롤해 과거 대화를 로드하는 방식으로 찾기를 시도합니다.
4. 찾을 수 없다면 **원문 보기/복사** 기능을 대체 수단으로 사용할 수 있습니다.

> 이 기능은 기존 `zeta-chat-search`와 유사한 목적을 갖지만 **항상 직접 이동을 보장하지 않습니다.** 제타 가상 스크롤·메시지 DOM 구조에 좌우됩니다.

## 9. 전체 서사 상기 — 간략/표준/상세

**「전체 서사 상기」**는 **「모순 정정」과 별개**입니다.

지금까지 기록된 이야기, 고정 설정, 날짜별 사건, 인물 관계, 아직 해결되지 않은 사건을 모아 제타 채팅창에 붙여 넣을 수 있는 텍스트로 만듭니다.

| 모드 | 포함 내용 | 현재 코드상 최대 길이 |
| --- | --- | --- |
| **간략** | 핵심 설정과 주요 사건 중심 | 약 2,800자 |
| **표준** | 날짜별 주요 사건, 인물, 현재 관계, 복선 등 | 약 8,000자 |
| **상세** | 위 내용에 인물별 지식·일반 기억까지 최대한 포함 | 약 28,000자 |

- **미리보기**로 내용을 확인한 후 **「전체 서사 상기 복사」**를 사용할 수 있습니다.
- 상기문은 **기존 로컬 기록**을 이용해 생성하므로 **복사 자체는 Gemini API를 추가 호출하지 않습니다.**
- 분량을 초과하면 일부 내용을 생략할 수 있습니다.
- 복사한 텍스트를 제타에 직접 붙여 넣어 사용해야 하며, **제타 AI가 이를 장기적으로 반드시 기억한다고 보장할 수는 없습니다.**

## 10. 자동 분석 ON/OFF 및 수동 분석

- **ON:** 전체 수집이 끝나고 API 키가 있는 상태에서 새로운 메시지가 확인되면 미분석 대화를 분석하도록 예약합니다.
- **OFF:** 새로운 메시지의 **AI 자동 분석**을 중지합니다. 저장된 기록을 열람하거나 수동으로 수집·검색하는 기능은 계속 사용할 수 있습니다.
- **미분석 대화 요약:** 필요할 때 직접 Gemini 분석을 실행합니다.
- **중지:** 진행 중인 수집 또는 분석에 중지 요청을 보냅니다. 이미 전송된 API 요청은 취소 시점에 따라 완료될 수 있습니다.

자동 분석 ON/OFF는 **검열 느슨 ON/OFF와 다른 설정**입니다.

## 11. Gemini 모델, 검열 느슨, 토큰 사용량

### API 설정

- 기본 모델: `gemini-2.5-flash`
- 모델 이름을 설정에서 변경 가능
- Gemini API 키를 별도 입력·저장·삭제 가능
- API 키는 **Tampermonkey 저장소**에 보관하며 JSON 백업에 포함되지 않음

### 검열 느슨: 항상 켬

스크립트는 지원되는 네 가지 안전 카테고리의 요청 차단 임곗값을 `BLOCK_NONE`으로 고정해 Gemini API에 전송하도록 작성되어 있습니다. 이 설정은 별도 OFF 버튼이 없습니다.

**주의:** 실제 Google API에서 해당 설정을 허용하지 않을 수도 있으며, Google의 정책 및 기타 안전 제한은 그대로 적용됩니다. 민감한 내용이 반드시 처리된다고 보장하지 않습니다.

### 사용량과 예상 비용

- 성공한 Gemini 호출 횟수
- 입력 토큰, 출력 토큰, 사고 토큰 및 캐시 토큰 관련 사용 통계
- 사용자가 설정한 **입력·출력 단가**에 따른 예상 비용

을 확인할 수 있습니다.

**단가 입력값은 스크립트에서 자동으로 공식 요금을 조회한 값이 아닙니다.** 기본 단가는 예시 설정이며 실제 사용하는 모델·가격 정책·토큰 종류에 맞게 직접 수정하세요. 표시된 비용은 **실제 Google 청구서가 아닌 추정치**입니다.

## 12. 기록 수정, 초기화 및 JSON 백업

### 수동 편집

각 기억 카드에서 **편집 → 저장**으로 내용을 변경할 수 있습니다. 수동 편집 항목에는 보호 표시가 적용되어 다음 자동 분석에서 AI가 덮어쓰지 않도록 설계했습니다.

### 요약 전체 재분석 준비

설정의 **「요약 전체 재분석 준비」**는 자동 생성된 누적 요약을 초기화해 다시 분석할 수 있도록 합니다. **수동 편집 및 고정된 기억은 유지**하도록 설계되었지만, 중요한 기록은 먼저 백업하세요.

### 채팅방 JSON 백업 및 복원

- **「이 채팅방 JSON 백업」**: 채팅방 ID, 누적 기억, 원본 메시지를 JSON으로 저장
- **「JSON 복원」**: 해당 채팅방의 기존 원문·기억을 백업 데이터로 **교체**
- 다른 채팅방 ID의 백업은 바로 복원되지 않도록 검사
- Gemini API 키는 백업에 포함되지 않음

> **백업에는 실제 대화 내용이 포함되어 개인정보나 민감한 서사가 들어갈 수 있습니다.** 공개 GitHub 저장소·게시판·클라우드 공유 폴더 등에 업로드하지 마세요. JSON 복원은 기존 기록을 대체하므로 먼저 별도로 백업하는 것이 좋습니다.

## 13. 자주 발생하는 문제

### Q. 채팅방 안인데 「채팅방을 열어 주세요」 또는 「채팅방 ID를 감지하지 못했습니다」가 표시돼요.

`0.0.4`에서는 **모바일 Safari의 페이지 통신 연결 문제에 대응**하기 위해 `unsafeWindow` 연결 및 보조 통신 경로를 추가했습니다.

다음 순서로 확인하세요.

1. 설치된 유저스크립트 버전이 **0.0.4**인지 확인합니다.
2. 제타의 **실제 대화 화면**에서 새로고침합니다.
3. 말풍선이 로딩된 후 기억 보조 패널을 다시 엽니다.
4. 화면에 **「연결 재확인」** 버튼이 나타나면 실행합니다.
5. 계속 실패하면 Tampermonkey의 스크립트 활성화 및 해당 도메인 접근 허용 여부를 확인합니다.

위 방법으로도 해결되지 않으면 제타의 인증 요청 감지 구조가 달라졌을 수 있습니다. **현재 0.0.4가 모든 Safari 버전에서 해결된다고 보장할 수는 없습니다.**

### Q. 수집이 계속 0건이거나 일부만 불러와져요.

- 실제 제타 채팅방에 메시지가 있는지 확인합니다.
- 페이지 새로고침 후 다시 **과거 대화 전체 불러오기**를 실행합니다.
- 인증 확인 대기, API 응답 실패, 요청 제한 또는 제타 API 변경일 수 있습니다.
- 전체 수집 미완료 상태에서는 누락 방지를 위해 요약 분석이 차단될 수 있습니다.

### Q. 기억 요약이 시작되지 않아요.

전체 대화 수집 완료 여부와 설정의 Gemini API 키를 확인한 후 **미분석 대화 요약**을 눌러 보세요. API 오류가 나면 요청 제한, 모델 이름, 키 권한, 안전 설정 허용 여부를 확인합니다.

### Q. 원문 이동 버튼을 눌렀는데 해당 말풍선이 안 보여요.

현재 제타 화면에 없는 과거 메시지는 스크롤로 불러오려고 시도하지만 항상 성공하지는 않습니다. 먼저 **원문 보기**에서 내용을 확인하세요.

### Q. 자동 분석을 꺼도 기존 요약을 볼 수 있나요?

예. ON/OFF는 자동 Gemini 분석 여부를 제어합니다. 저장된 데이터는 별개입니다.

### Q. 다른 기기에서도 기억이 자동으로 공유되나요?

아니요. 데이터는 기본적으로 **해당 브라우저의 로컬 저장소**에 보관됩니다. 다른 기기에서는 JSON 백업·복원을 이용해야 합니다.

## 14. 개인정보 및 보안 안내

- 대화 원문과 서사 기억은 기본적으로 브라우저의 **IndexedDB**에 저장됩니다.
- Gemini 분석 또는 AI 자연어 답변을 실행하면 **관련 채팅 내용과 누적 기억이 Google Gemini API로 전송**됩니다.
- 제타 인증 헤더는 대화 수집 과정에서 사용되며, 이 스크립트는 **GitHub나 별도의 개발자 서버로 채팅 원문을 전송하도록 설계되지 않았습니다.**
- **API 키를 저장소, 이슈, 스크린샷, 공개 백업 파일에 게시하지 마세요.**
- API 키를 타인이 사용하는 환경에서 보관하지 않도록 주의하세요.
